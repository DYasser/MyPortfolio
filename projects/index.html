01Personal project

budget.io

A recurring-budget planner that runs entirely in your browser.

Angular TypeScript Chart.js PWA

You describe what you earn and what you owe, along with how often, and it expands those rules into real dates: a doughnut chart of where the month goes, a colour-coded calendar of every due date and payday, and a savings projection towards a target. It installs as a PWA and works offline.

The interesting part

It has no backend, and that is a decision rather than an unfinished feature. A personal budget is about as sensitive as a document gets, and the app has no multi-user requirement, so the data never leaves the machine it was entered on — nothing to breach, no latency, and no infrastructure to keep alive for the demo to still work in two years. The cost is real and worth stating: the data is per-browser, so Settings has JSON import and export as the escape hatch.

02CERN

SWAN Gallery

A JupyterLab extension built during my internship at CERN.

TypeScript Python JupyterLab MkDocs

SWAN is the service physicists use to run their analyses in the browser. The gallery lets someone browse a catalogue of example notebooks and open any of them in their own session in a single click, instead of hunting for files and copying them by hand. It is still running at CERN today.

The interesting part

The catalogue is an MkDocs site hosted in an IFrame, which talks to the JupyterLab frontend over postMessage; a Python backend fetches the notebook and hands back the path so the file opens on its own. My favourite part was a re-entrancy bug: reopening the gallery stacked duplicate handlers, so one click downloaded the same notebook several times. A guard flag in the execute path fixed it.

03Chrome extension

Incognito Opponent

A Chrome extension that hides your opponent on Chess.com.

JavaScript Chrome API CSS

Knowing you are up against a much higher-rated player changes how you play before a move is made. This hides your opponent by name for the length of the game and reveals it once the game ends, so the position is all you are reacting to.

The interesting part

The interesting part is that a name is not in one place. It appears in the player card, in the chat as messages arrive, and again in views the site renders after the game starts — so a single pass over the DOM is not enough. The extension watches for the nodes as they appear and scopes itself strictly to Chess.com so it cannot touch any other site.
